# Full review (19 Oct 2026): fix list

Three read-only reviews (guest pages, admin, API). Tick items off as they're fixed. Severity first.

## API: security and data (do first)
- [x] **HIGH: name lookup returns the full guest link.** `POST /p/:slug/find` returns `invitation.token`. Names are public on the message board, so anyone can take over another guest's RSVP, messages and board identity.
  - Fix: don't return a token. Text the link to the phone on file, or ask for the last 3 digits of the mobile. Rate-limit per wedding too.
- [x] **HIGH: inbound "No worries…" or "Sorry… yes" counts as a decline.** The decline then wipes seat, diet and meals.
  - Fix: act only on whole-message yes or no. Anything mixed or unclear goes to "Needs you". Add tests.
- [x] **HIGH: `person.table_id` is one seat across all events.** Saving event B's plan clears event A's seats, and the per-event seated counts are wrong.
  - Fix: a `seat_assignment(person_id, event_id, table_id)` table, or update only the people whose seat in this event's tables changed. Filter `data.ts` by event.
- [x] Texts PATCH: a losing concurrent save still rewrites the send dates. Claim the version first.
- [x] The couple's Messages replies ignore quiet hours and the daily cap (they use the URGENT 'reply' kind). Give them their own kind.
- [x] Queued `manual:` and `auto:` texts still go out after the guest is deleted or excluded, or the campaign is deleted. Re-check before sending, and cancel on delete.
- [x] A shared mobile with 2 invitations in one wedding: a texted RSVP lands on an arbitrary one. Don't auto-act; send it to "Needs you".
- [x] Inbound forwards to the admin's mobile have no limit, so they can run up costs. Rate-limit per (wedding, phone) and per wedding.
- [x] Viewer role receives guest tokens (pages samples, guest links), so a viewer can write as any guest. Give tokens to owners and editors only.
- [x] Guest photo storage cap and dedupe (done 19 Oct: 150 per hour, 600 per day, 9 GB per wedding, SHA dedupe).
- [x] Lost updates to `wedding.content` from board settings and share on/off. Use `json_set` on the sub-key, or a version check.
- [ ] Settings GET/PUT runs `estimate()` per campaign, which is about 80 queries. Load once.
- [ ] `loadWedding` reads all SMS history and runs on every single-guest edit. Use a grouped last-text query and a single-guest loader.
- [ ] Cron re-inserts every invitation each run. Use NOT EXISTS, and skip weddings that are over. `matchPhone` is N+1.
- [x] Event delete isn't atomic. `{table}` can read a deleted event or a guest who declined.
- [x] Board like: no rate limit, and a double tap returns 500. Use ON CONFLICT and `allow()`.
- [x] Messages reply says "texted" when there is no sender or texts are paused.
- [x] Soft-delete filters missing on events in admin RSVP PUT and `data.ts` rsvps.
- [x] Login throttle is per IP only. Add a per-email limit.
- [x] Viewer GETs mark messages read. Only do that for owners and editors.
- [x] The music URL points to a missing `/api/p/:slug/media/:key` route.
- [x] Unguarded `JSON.parse` on stored JSON (board, settings, texts, guest, seating, events).
- [x] Purge expired sessions and `rate_limit` rows in the cron.
- [x] "Days to go" ignores the wedding's timezone.
